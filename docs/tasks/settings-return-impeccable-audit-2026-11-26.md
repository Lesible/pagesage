# 设置返回流程：Impeccable 原生界面审核

日期：2026-11-26。范围：从阅读器打开 AI/翻译设置、切换分类及返回，
以及设置的窄屏分类页。模式为 Operate，保持既有 Material 控件、配色与信息结构。
采用 Impeccable `audit.native`、Android 平台参考和 `polish` 方法。

## 平台一致性结论

现有 Material 按钮和 Navigator 路由可以沿用，无需重建导航系统。
首次修复稿补上了明确的「返回阅读」，但窄屏把返回入口放在滚动内容中，
二级分类页还没有 SafeArea；切换分类后缩窄窗口时标题还会沿用最初入口。
这三处已在审核后的修整中关闭，证据见末尾。
原生 Flutter 不使用浏览器/CDP 检测器；以下依据源码、组件行为与离屏截图，
不代表 TalkBack、真实系统返回手势或设备帧率已验收。

## 已确认问题（本轮已修复）

### [P2] 窄屏设置标题和返回动作随正文滚走

- 位置：`lib/features/settings/presentation/settings_page.dart` 的窄屏直接入口、
  分类首页与 `_openMobileSection`。
- 类别：自适应 / 导航可用性。
- 影响：长配置表单滚动后，窄屏桌面用户必须先回到顶部才能退出设置。
- 证据：`impeccable-baseline.log`，380 宽普通/两倍字号和设置二级页滚动后，
  返回按钮的 `hitTestable()` 断言失败。
- 建议：标题栏固定在滚动区外，只让设置正文滚动。对应 `/impeccable adapt`，
  最后 `/impeccable polish`。

### [P2] 设置二级页未显式保护系统安全区

- 位置：同文件 `_openMobileSection`，原来为 `Scaffold → ListView`。
- 类别：平台一致性 / 安全区。
- 影响：显式列表 padding 无法表达状态栏和屏幕切口，需要靠碰巧足够的留白避让。
- 证据：源码；补充带系统 inset 的 widget 测试。未据此声称实际 Android 已发生遮挡。
- 建议：与窄屏直接入口共享 SafeArea 和固定标题布局。对应 `/impeccable adapt`，
  最后 `/impeccable polish`。

### [P2] 桌面切换设置分类后缩窄窗口，标题仍取初始入口

- 位置：同文件直接入口窄屏标题原来仅由 `initialAi` 决定。
- 类别：自适应 / 信息一致性。
- 影响：从翻译切到阅读后缩窄窗口，阅读设置会显示为「翻译设置」。
- 证据：标题表达式与可保留的 `_selectedSection` 不一致，增加 1280 → 380 → 1280
  的分类与返回入口测试。
- 建议：标题取当前分类，保持导航身份与内容一致。对应 `/impeccable adapt`，
  最后 `/impeccable polish`。

## 已关闭的原始问题与正向结果

- 阅读器的翻译设置入口漏掉返回动作、窄屏忽略初始翻译分组，均已在本轮修复。
- 返回标题不会因为从「翻译」切到「阅读」而丢失；一般压栈入口显示「返回」。
- 主导航设置首页不会因上方弹出临时对话框而误显示返回入口。
- 网页真实阅读器测试确认返回同一 renderer、同一快照路径和滚动偏移，
  不额外调用翻译服务；PDF 返回同一 Canvas；AI 未发送问题保留。
- 截图中的字体方块来自离屏测试未注册控件字体，并非已确认的应用字体故障；
  应完善测试字体装配后再判定，不能据此改生产字体。

## 修整后的复核

三项问题均已修复：

- 窄屏分类首页、AI/翻译直接入口、分类二级页共用固定标题的
  `_CompactSettingsLayout`；标题区在滚动正文之外。
- 该布局统一使用 SafeArea，带 64 逻辑像素顶部 inset 的组件测试通过；
  返回设置入口在正文滚动后仍可点击。
- 标题随当前 `_selectedSection` 变化；桌面选择阅读后缩为 380 宽、再展开，
  标题与分类一致，返回动作始终保留。

复核参考分为 **16 / 20**（无障碍 3、性能 3、主题 4、平台一致性 3、自适应 3）。
这次已确认的问题全部关闭；不以离屏结果冒充实际读屏、设备手势或性能测量，
因此没有给出全项满分。
