# 网络书首版实现与验证

日期：2026-11-26。本文记录实际实现，取代早期草案中尚未落地的类型与存储建议。
最终回归与 Linux 安装核对已完成，以下“已实现”不代表全部设备人工验收。

## 使用路径

1. 书库「导入」菜单 →「新建网络书」→ 输入书名。
2. 章节管理中输入完整 HTTP/HTTPS 网页地址，点击加号保存。
3. 已保存章节可进入现有原生阅读器；桌面及移动目录均分「章节」「本页大纲」。
4. 「添加或管理网页」可改章节名、上下移、移除、单章刷新、整书刷新和查看来源信息。
5. 任务中心可取消正在保存的网页或整书刷新；失败后从网络书章节管理重试。
6. 备份会带上网络书正文、图片及历史快照，恢复到另一数据目录后仍可离线阅读。

创建空网络书不会要求选择文件，不把网页书籍伪装成 Markdown 文件夹。重复添加同书
相同 URL 只保留一个活跃章节；保留 query、移除 fragment，不跨书去重。

## 实际数据与发布契约

- schema **12 → 13**，新增 `web_chapters`、`web_snapshots`，不重建或清除旧书库。
- `BookFormat.web`、`ReadingLocatorType.web` 使用独立类型。
- 章节、快照为 UUID。定位携带 `webChapterId`、`snapshotId`、`sourceRevision`、
  `textRevision` 和章内 UTF-16 区间；排序号与 URL 不作为持久引用身份。
- 章节存来源网址、自定义标题、顺序、操作 epoch、当前快照与最近错误；
  快照存最终网址、正文/文本版本、清单 hash、占用和 HTTP validators。
- 复用 `DocumentSources` 保存稳定章节来源；复用已有任务表和取消注册表保存
  `webCapture` 操作，未额外增加一套 WebOperations 账本。
- 先写完整 staging 目录、flush、rename 为不可变快照，再在数据库事务中
  检查章节未删除、epoch 和旧快照未变后发布。取消、抓取/解析失败不改旧指针；
  已写但未发布的本次候选会清理。
- 不自动迁移已有批注到变化后的文本。历史书签、批注、笔记和 AI 来源仍打开对应
  快照；渲染器只画同章节、同快照的批注。当前会话固定版本，刷新后从章节列表
  明确打开新版，不在选区或输入过程中自动替换。

路径为应用管理的持久目录：

```text
library/web/<bookId>/
  snapshots/<snapshotId>/
    manifest.json
    article.xhtml
    resources/<sha256-url>
  staging/<candidateId>/
```

首版采用**每快照自包含资源**，没有实现早期草案的跨快照共享对象池。
已发布历史快照暂不自动 GC；移除章节仅软删除并退出当前列表/正文搜索。移除书籍的
数据库行沿现有删除语义处理，受管历史文件暂不自动物理回收，因此磁盘占用可能累积。
备份只收冻结数据库引用的快照，不收 staging、无引用候选或外部 Markdown 源目录。
后续做物理回收时，必须先实现备份/会话引用保护，不能直接删除旧目录。

## 抽取、网络与原生阅读

- 正式代码复用 W0 已验证抽取器：语义文章/main 优先，缺少语义结构时 reader_mode
  HTML adapter 回退。`html 0.15.6` 和 `reader_mode 0.2.3` 为纯 Dart 依赖，
  应用运行不需要 Python、浏览器或 JS 运行时。
- HTML 白名单清理后由 `NativeHtmlParser` 转成原有原生 block 模型，保持代码、表格、
  链接、大纲及文本偏移；只装载当前网页。未知远程资源不会在打开正文时请求网络。
- 单次请求 30 秒、最多 5 次跳转；HTML 10 MiB，单图 20 MiB、40M 像素，
  每章下载图片合计 100 MiB；图片阶段约 60 秒预算，到达预算后保留正文并提示缺图。
  缺失图片不算完整保存，可重新刷新补齐。
- 条件 GET 只在本地正文、清单、资源均校验通过且没有资源缺失时启用。
  304 保留原快照；本地文件损坏或缺图时发完整请求。200 内容未变则不新增发布版本；
  本地损坏时即便远端内容 hash 相同也发布修复后的副本。
- 整书刷新冻结章节清单，逐章处理，有父任务和逐章任务，取消后停止剩余章节。
- 已保存网页链接优先在书内跳转；其他网页链接提供打开浏览器或主动加入章节的选择。
- 来源详情显示最终网址、保存/检查时间和当前版本占用；缺图和不支持媒体有明确状态。

## 搜索、AI 与备份

- 逐章读取当前快照切块；搜索 locator 和文本版本均指向对应网页快照，
  不通过合并全书制造伪章节。新快照/章节变动使旧索引失效，完成后发布新代。
- 搜索代发布在 SQLite 事务内比较输入 revision，拒绝过期生成结果覆盖新内容。
- 当前章 AI 上下文读取 locator 指定的本地快照；整书范围继续走已有检索。
  笔记、书签、批注和 AI 导出沿用结构化 locator，保留历史版本身份。
- 含网络书时使用备份 manifest v2，列出快照文件大小与 SHA-256；无网络书可继续生成 v1。
  恢复支持 v1/v2，含网络书却缺资源的旧备份明确拒绝。
- 从冻结 SQLite 选择快照，逐文件校验并排除符号链接/路径穿越/重复条目。
  恢复上限为网页资源合计 2 GiB、100000 文件；网页文件与数据库一致后重定位
  书籍根目录，和数据库/封面一起执行安装与失败回滚。
- 现有恢复流程不新增进程崩溃恢复 journal；运行时失败的回滚测试不能替代断电验证。

## ReaderPage 拆分

本轮按用户追加要求抽出：

- `WebReaderSession`：当前快照、异步代际、切章和渲染进度选择。
- `ReaderWebDocumentGate`：装载、空书/错误及资源缺失提示。
- `reader_contents_sheet.dart`：EPUB/Markdown/网络书目录弹层和定位转换。
- `ReaderMobileOverlay`：移动顶/底栏、显隐过渡和恢复按钮。
- `reader_external_link.dart`：链接确认、已保存网页定位及添加章节。

`ReaderPage` 继续负责阅读交互编排，不使用 part/私有扩展把同一状态简单分摊到多个文件。
相对本轮开始版本净减少 166 行，当前 3830 行；本轮新增网页逻辑主要由上述独立职责承接。
桌面大纲按当前网页偏移选中一个位置；切网页保留目录页签选择。
