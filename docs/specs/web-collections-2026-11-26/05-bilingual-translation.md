# 双语对照阅读与翻译服务配置

日期：2026-11-26。状态：供应商配置、网页段落对照、PDF 按页入口与持久译文已接入。
供应商接入见[配置任务](../../tasks/translation-providers-2026-11-26.md)，
当前实际契约、交互和验证见[阅读器打磨任务](../../tasks/web-reading-polish-2026-11-26.md)。
本设计与网页合集共用正文 block、来源快照和原生渲染；先修正文抽取和定位，
不把整页网站导航、推荐文章或代码直接作为一大段送去翻译。
用户同日追加 PDF 当前页翻译与持久保存，已纳入本设计，不再列为首期排除项。

本轮采用 schema 14 的单张完成片段表，并保留片段级失败重试；
进入对照先读本地，点击本页/当前网页翻译后补缺失。下面的自动可见段预取、
跨快照内容复用、三实体作业模型、强制重译历史、术语表和 PDF 几何级互相定位
属于后续目标设计，不能当作当前交付事实。EPUB/Markdown 本轮统一目录，
双语仍仅接入网页与 PDF。

## 1. 本次新增需求

- 桌面支持左原文、右译文；可切换仅原文、双语、仅译文。
- 同一语义段落对齐，支持同步阅读；窄屏改用段落下方显示译文。
- 翻译服务和目标语言可配置；可使用已有 AI 服务，也可使用专门翻译 API。
- 已有译文保存本地，断网仍可读，刷新网页后不能错配旧译文。
- PDF 支持一次翻译当前页，左侧保留原始页面，右侧显示对应译文；
  关闭重开仍可读，不因重新打开或切换布局重复请求。

网页和 PDF 共享配置、翻译适配器、持久译文及任务状态；来源抽取与布局分别实现。
EPUB/Markdown 后续接入；PDF 首期不做把译文重绘回原 PDF、重排为等版式 PDF 的导出。
参考沉浸式翻译的分段双语与 PDF 对照体验，不把浏览器插件或整套云端文档服务嵌入应用。
沉浸式翻译官方提供基础/高级 PDF、对照和导出，并有译文缓存/清理行为；
本项目的已完成译文是用户可管理的持久数据，不依赖浏览器缓存的有效期。

## 2. 阅读交互

### 2.1 同一列表内的成对 block

不使用两棵独立长列表按滚动百分比硬同步。原文与译文长度不同，
图片与字体变化也会改变高度，这种方式越读越错位。

每个条目绑定一个原文语义单元：

- 桌面条目左右两列，行高取两边较高者，段首自然对齐。
- 长段按语义拆为有来源映射的子单元，不因某一边过高而产生整页空白。
- 图片、表格、代码等特殊块单独处理；图片和代码默认只显示一次，不重复占满两列。
- 跳转与阅读进度保存 `sourceBlockId + 章内原文偏移/条目内比例`，不保存列内绝对像素。
- 侧栏仍区分章节与当前网页大纲；双语模式不另建第二套书籍目录。
- 开启对照后，按当前配置翻译可见段及有限预读段；显示正在联网处理的范围。
  整章翻译是单独操作，不因滚动或打开书籍自动发送整本。

移动端和窄窗口采用“原文段落 → 对应译文”的上下布局；
切回宽屏或改变列宽时，依据原文锚点保持当前位置。

### 2.2 状态与操作

- 阅读器只增加一个双语模式入口；菜单包含语言、服务选择、翻译本章和重试失败段落。
- PDF 对应入口主操作为「翻译本页」，菜单放语言、服务、查看已译页及「重新翻译本页」；
  本期不因翻到下一页自动翻译该页，整本批量翻译另行排期。
- 设置入口能直接回到阅读，保留位置；不弹出一连串配置确认框。
- 每段区分未翻译、排队、翻译中、成功、失败、已过期、已取消。
- 翻译失败显示原文与可重试状态，不把空字符串当成功，不挡住整篇阅读。
- 服务缺失/凭据失效时仍展示已有译文，提示修复配置；不自动换另一家上传内容。
- 首期批注和书签以原文定位为权威；从译文选区引用时说明“对应原文段落”，
  不把译文字符偏移冒充原文精确划线。译文自身批注需独立定位命名空间，后续扩展。

### 2.3 PDF 按页对照

PDF 保持原始版面，不能直接套网页成对段落的行高规则：

- 宽屏左侧原 PDF、右侧当前页译文；翻页同时切换两侧页身份。
  右侧译文可独立滚动，不能按两侧滚动百分比硬同步，也不把长译文缩小塞进原文文字框。
- 通过段落 ID 与原文框建立对应：点选译文段落时定位/强调原页相应区域；
  支持框的段落可反向定位译文。译文高度变化不改变原文页号。
- 窄屏保留当前页，可切原文/译文，或在该页下方显示译文；切布局仍保存原文定位。
  原文进度是阅读权威；译文面板的滚动位置单独保存，不反写原文阅读位置。
- 页内长表格、代码与公式不强求逐行双栏对齐；保持行列、编号与引用关系，
  不能确认结构时明确降级为本页译文，不显示伪造的精确段落对应。
- 空白页、纯图片但 OCR 无文本、加密/不可解析页显示各自原因，不缓存空字符串为成功。

当前代码可复用的部分与必须补齐的边界：

| 链路 | 已有事实 | 翻译需要补齐 |
| --- | --- | --- |
| 原生 PDF 文本 | `PdfCanvasRenderer.textOfAsync` 有页级文本/几何与 worker；搜索用 `PdfTextExtractorService.extract` 遍历文档 | 数据层提供按需页级来源 adapter，转换为领域单元；不能为译一页调用整本文本抽取，也不能让翻译领域依赖渲染 Widget |
| 本地 OCR | `OcrPageResult` 有文本、版本/签名和可选的归一化行/词框 | 优先复用有效结果，无有效文本层才调用现有 OCR；行/词框需合为语义段，不把框列表直接当阅读顺序 |
| 原文对应 | 现有 PDF 选择/批注以原始页面定位 | 统一到旋转、裁剪后的显示页归一化坐标；领域页号 1-based 与渲染 index 0-based 只在 adapter 转换 |

抽取按页判断，不能因一本 PDF 某页有文字就认为所有页可直接翻译：

```text
当前页 + 文件来源版本
  → 有效文本层的文字与几何
  → 无有效文本时复用/执行当前页本地 OCR
  → 阅读顺序与语义分段
  → 匹配已有译文；仅对缺失单元调用当前翻译服务
  → 校验结构 → 持久提交 → 本页对照
```

多栏页面需要列检测与阅读顺序规则；页眉/页脚单独识别，不能混进正文断句。
连字符换行按语言与原文映射处理；公式、编号、代码和链接必须保护。
首期不合并跨页句子，翻译请求范围是当前页；若后续增加相邻页上下文，
需明确显示实际范围并将该上下文纳入缓存指纹。
OCR 几何缺失时仍可页级对照，不能捏造框；总置信度只作来源提示，不当作每段置信度。

## 3. 翻译单元与安全结构

1. 从抽取后的正文 block 划分单元，不从 DOM 导航或整页 `innerText` 直接切长度。
2. 标题、自然段、列表项、图注、表格单元格可译；代码块、URL、公式表达式、
   文件名和技术标识默认保留。
3. 单元记录原文来源、快照、textRevision、block 路径、UTF-16 半开范围与文本 hash。
   snapshot 内身份稳定；跨 snapshot 的复用要验证文本和上下文，不保证序号永远稳定。
4. 内联链接、强调和术语采用受控 span/占位符。响应必须核对单元数、ID、
   占位符与结构，不能把丢了链接或代码的输出标记为完整成功。
5. 翻译服务返回的 HTML 仍是不可信输入；按本地结构重建，不能插入浏览器执行。
6. 普通 LLM 使用翻译任务和结构化输出，不携带聊天历史、检索出的其他书籍或用户笔记。
   网页内的指令只是待翻译资料，不具有操作工具或改变请求范围的权限。

批量上限由适配器能力控制：请求文本条数、字符数、UTF-8 字节数与模型 token 限额
分别计算。不要用一个固定“每段 N 字”参数套所有厂商。

不能因 OpenAI-compatible 外形而省略其翻译专用参数。
该顺序基于接入条件和公开价格，不是未测试的质量排名；
厂商并行实现不阻塞先交付网页/PDF 的缓存闭环。

## 5. 配置管理

### 5.1 独立业务配置，共享凭据基础设施

现有代码已有 `AiProfile`、revision、凭据状态和 `AiCredentialGuard`。
翻译应复用其安全存储和可恢复写入方法，但不把所有翻译厂商硬塞成一种聊天配置。

拟议 `TranslationProfile`：

- `id, name, provider, revision, enabled`。
- `endpointPreset / validatedCustomEndpoint`、`apiVersion`、`region / projectId`（按 provider）。
- `model`、默认源/目标语言、风格、术语表引用/版本、非敏感 provider 专属选项。
- `credentialRef` 或 `aiProfileId`，二选一；`credentialState` 可观察。
- 并发、超时、重试与用量预算是运行参数；不与译文质量选项混成一大块 JSON 编辑器。

数据库不存 API secret。百度 APP ID、有道 appKey 等标识也要作为用户配置谨慎展示；
secret、签名、Authorization 和正文不能进入普通日志。
自定义敏感 headers 同样进入安全存储，不能放进“高级选项 JSON”明文保存。

引用 AI profile 时只存其 ID，发送前冻结可用配置 revision 并由统一凭据访问层取密钥，
不复制出第二份 key。修改/删除配置采用乐观锁和可恢复操作：

- 密钥确认可写后提交配置，不出现永远“正在更新”。
- 删除被引用的 AI 配置时选择替代或将关联翻译配置标记不可用；缓存译文保留。
- 在途任务冻结输出配置，删除/取消或更新后的迟到响应不能覆盖新任务。
- key 轮换、改配置名称和并发调整不必清空已有译文；输出语义改变才影响新缓存键。

### 5.2 用户界面与默认值

设置增加「翻译」分组，服务列表支持新增、编辑、测试、设默认和删除；
凭据字段随 provider 变化，只呈现适用项。选择“使用已有 AI 配置”直接引用已有列表。

设置继承：阅读会话临时选择 → 单书设置 → 全局默认。
默认源语言自动识别，目标语言初始跟随用户界面语言；可固定语言对。
默认布局“宽屏左右，窄屏上下”，列宽可调整；保留术语与代码的默认规则。

“连接测试成功”只说明指定固定短句请求通过，不等于真实长文质量、术语正确或剩余额度足够。

## 6. 本地缓存、更新与备份

### 6.1 持久语义与身份

译文存 Drift/SQLite 独立表，不覆盖原文，也不回写用户的外部 Markdown 文件。
已完成译文不设默认过期清理，不随退出、清临时文件、移除服务配置或内存 LRU 淘汰而删除。
界面称「已保存译文」，展示页数/大小，并提供单页或按书删除；
移除书籍时按关联规则删除，不能误删仍被其他来源引用的去重内容。

拟议职责（逻辑实体，不代表本次已增加数据库表）：

- `translationContents`：不可变的原文/上下文 hash、输出指纹、校验通过的译文、用量、
  服务/模型身份及创建时间；保留 `cacheKey + resultRevision`，
  不能把 cacheKey 单列唯一，妨碍强制重译保留旧结果。
- `translationBindings`：书籍、来源版本、格式/页号或 snapshot/block/range、
  来源单元 ID 与几何、当前接受的内容版本 ID。
  来源单元/输出指纹的当前绑定唯一；事务内核对 generation 后切换引用。
  几何和位置属于来源绑定，不混入译文字符串。
- `translationJobs`：冻结的输入/输出身份、运行状态、generation、取消及错误分类；
  重启时在途任务恢复为可重试，不能声称服务端已完成或假定上次调用没有扣费。

建议缓存键包含：

```text
source text hash + context hash + source/target language
+ provider/model + output options fingerprint + glossary revision
+ segmentation version + prompt/template version
```

输出指纹包含影响服务语义的 endpoint/模型/术语选项，但不包含密钥、配置显示名、
并发数或临时请求 ID。profile revision 用于并发保护，不直接充当译文内容版本。

译文条目还绑定来源 snapshot/block/range；缓存内容复用与位置绑定分开。
网页刷新后，相同文字和有效上下文可复用并建立新位置映射；改动单元重译。
当前会话仍使用旧快照时，两列都保持同版，不能一边原文新、一边译文旧。

PDF 绑定增加 `sourceRevision + pageNumber + extraction/textRevision +
layout/segmentationVersion + sourceUnitId`，并保留必要原文/几何来源。
OCR 更新导致文本/分段变化时重新检查绑定；内容与上下文确实未变的译文可以复用，
不能只因重新 OCR 就全页重扣费，也不能仅凭页码命中其他版本的译文。
只改变缩放、主题、列宽或显示名时不重译。

### 6.2 持久提交、重试与费用

- 进入页面先本地查询；命中当前语言和输出配置的有效译文时不发网络请求。
  离线与凭据丢失仍能读已保存内容；切到尚未缓存的语言应显示缺失，而非展示错语言。
- 同页同键在途去重；分块成功即持久提交，部分失败后重试只补失败/缺失块。
  不能整页全成功后才一次保存，导致退出或限流丢掉已付费结果。
- 「重新翻译」创建新 generation，旧译文保留到对应新结果校验并提交成功；
  失败仍可读旧版本。服务/模型变化可查看已有版本，不自动收费刷新。
- 翻页/关闭/取消之后的迟到结果不得改变当前页或覆盖新 generation。
  若任务仍有效，可以按原冻结来源保存；书籍删除后的响应不得复活关联数据。
- 本地落盘失败不得显示「已保存」；保留会话中已收到结果并允许重试保存。
  UI 同时区分已获取/未保存与服务调用失败，避免用户为写盘失败再次请求。
- 超时或连接中断不等于服务端未计费；不承诺网络调用恰好一次。
  已知限流可退避，不对未知结果无限自动重发；显示可能再次产生费用。
- 模型输入/输出 token 与传统服务字符分别记录；金额只是按带日期价目表估算，
  无 usage 返回时标记估算，不伪造服务账单或剩余额度。

原文书签、笔记和进度仍按原文保存。译文若增加搜索，必须有独立 source kind 与
返回定位，不混用原文 FTS offset。首期保留现有原文搜索行为。

### 6.3 备份与恢复

本轮 schema 14 完成片段随数据库进入备份，网页 v2 也含正文与资源；不备份密钥。
恢复重映射 AI 配置引用，并移除翻译密钥绑定，避免误用目标设备已有凭据。
普通 v1 仍只备份数据库与封面，不包含书籍文件；不能声称恢复数据库就能显示 PDF 原页。
恢复后有译文数据可离线阅读文本，原文左右对照还要求原 PDF 可用且版本匹配；
缺失时提示重新关联经身份验证的文件，不悄悄套用同名 PDF。
网页完整离线阅读也要求对应正文和资源已被备份。联网服务恢复后需要重新验证凭据。

## 7. 实施与验收

以下区分已经接入的阅读器路径与目标设计中尚未实现的扩展：

| 阶段 | 内容 |
| --- | --- |
| T0 | 两篇用户网页、文本 PDF/扫描 PDF/混合 PDF 建立评测；覆盖双栏、表格、公式、旋转页与 OCR 无框；术语、遗漏、结构、延迟、用量分别评价 |
| T1 | 基础 TranslationProfile、五家供应商、自定义/AI 引用及试译已实施；配置复用 AppSettings JSON，不单独增 schema；术语表待扩展 |
| T2 | 已实现有来源的段落/请求片段、保护代码/公式/URL、schema 14 完成片段缓存、取消/重试与 generation；未实现独立后台作业与强制重译版本管理 |
| T3 | 已接网页成对 block、PDF 当前页对照、窄屏布局，原文定位继续复用；原生组件与离屏验证通过，PDF 几何级互相定位未实现 |
| T4 | 已做快照/页文本隔离、缓存备份恢复；跨快照内容复用、真实费用统计和真实服务质量验收待后续 |

验收必须覆盖长译文高度、缺段/错 ID、代码/公式不被改写、语言切换、同文不同上下文、
配置切换迟到响应、取消/限流/认证失败、断网重启、网页刷新及删除配置后仍能读缓存。
还须以调用计数和真实文件库 close/reopen 证明：重复打开为 0 次网络、同页并发为 1 个
在途请求、成功块不重发、持久化失败不冒充保存成功、重译失败仍保留旧译文；
PDF 快速翻页不串页、OCR 更新不误用旧绑定，原始 PDF 缺失时恢复提示真实。
不得用“能调用接口”代替对照阅读完成。
