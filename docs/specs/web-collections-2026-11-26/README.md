日期：2026-11-26。状态：**网络书首版链路已实现，自动回归与 Linux 安装核对通过**。

[实现与验证](07-implementation.md)为准；既有 EPUB/PDF/Markdown 导入行为不变。

## 1. 目标与文档入口

用户可以创建一本书，把多个网页分别添加为章节，在同一个阅读器中阅读、标注和检索。
保存后的正文与受支持图片属于本地书库数据；断网可读，联网可手动更新。

## 2. 已确认需求

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| R1 | 创建网页合集，多个网页组成一本书 | 允许空合集；重启后书籍和章节仍存在 |
| R2 | 每个网页是独立章节 | 打开章节只加载对应正文，不合并全书网页 |
| R3 | 章节列表与当前网页大纲分开 | 切章更新大纲，但不强制切换侧栏页签 |
| R4 | 保存正文及阅读所需图片 | 断网、重启后可读；图片未保存须明确提示 |
| R5 | 手动刷新当前章节和整本合集 | 后台执行，有逐章结果、重试与取消 |
| R6 | 更新失败保留旧版 | 断网、超时、解析失败、磁盘满均不覆盖旧内容 |
| R7 | 延续现有深度阅读能力 | 进度、书签、划线、批注、笔记、搜索与 AI 来源可关联 |
| R8 | 更新不损坏阅读资料 | 不覆盖用户标题和顺序；保留历史摘录，无法可靠重定位时不画错高亮 |
| R9 | 本地备份可恢复网页内容 | 新备份包含必要快照和资源，换数据目录后断网可读 |

R1–R9 是交付范围。以下实现建议用于形成可执行方案，可以依据 W0 验证结果调整；
不能把“待验证方案”描述成用户额外设置的限制。

## 3. 首期实施边界

首期优先支持公开、以 HTML 正文为主体的文章、文档和教程页面：

- 提取标题、正文层级、段落、列表、引用、链接、代码、表格与受支持图片。
- 不强求复刻网站皮肤；正文使用 PageSage 的字体、主题和阅读设置。
- 保留原始网址、实际响应网址、获取时间和来源标题，允许打开原网页。
- 保留可表达的公式、图表替代文本和代码；无法渲染的内容给出提示或可读回退。
  不能把丢失关键公式、表格或图片的页面无条件标记为完整保存。
- 保存选定网页及其正文需要的资源，不递归抓取站内链接，不自动发现并导入整个站点。

登录态、强依赖 JavaScript 的单页应用、交互图表、音视频、跨页文章自动合并、
浏览器扩展和系统分享入口，留作后续增强。遇到这类页面要报告抽取边界、允许查看
已提取内容或打开原网页，不把登录页、验证码或“请启用 JavaScript”当作成功正文。
跨平台动态网页抓取方案在验证前不选定，也不把 Python 或浏览器运行时作为必装依赖。

创建、添加、刷新入口采用已有任务中心和主题组件；不增加云账号、云同步或在线代理服务。

## 4. 主要交互

### 4.1 创建与添加

1. 书库已有导入菜单增加「新建网页合集」，输入书名后创建空合集。
2. 空合集展示「添加网页」；已有合集在章节面板提供同一入口。
3. 首期添加框接收一个 HTTP/HTTPS 网址和可选章节标题；批量粘贴可后续增加，
   整本刷新不依赖批量粘贴功能。
4. 提交即创建稳定章节身份并显示获取进度；任务失败时保留可重试条目。
5. 首章成功后可进入阅读；阅读其他章节时添加网页，不强制打断当前阅读。
6. 同一合集重复添加规范化后相同的请求网址，优先定位已有章节并提供刷新操作。
   不按相同正文 hash 合并不同网页，也不跨书阻止收录同一网页。

规范化保留有意义的 query。仅 fragment 不同的同页链接优先打开已有章节中的锚点；
若 fragment 是网站应用路由，按不支持的动态页面处理，不假装已抓到指定内容。

### 4.2 阅读与导航

- 桌面侧栏区分「章节」和「大纲」：前者展示网页标题及保存状态，后者仅含当前网页标题树。
  移动端采用同语义页签/抽屉，不常驻遮盖正文。
- 章节标题可以改名、排序和删除；来源标题作为元数据单独保留。
- 大纲、书签和搜索点击按章节身份定位，不用章节排序号作为主键。
- 从章节面板切换网页后，仍留在章节页签；只高亮一个当前章节和一个当前大纲位置。
- 默认打开本地已发布版本，不等待联网检查，不暗中请求网页或远程图片。
- 正文链接先识别已保存章节和页内锚点；其他链接提供打开原网页或添加到合集，
  不因普通点击自动收录，也不在受控正文里执行脚本。
- 阅读器能查看来源、最后保存时间、最近检查时间和图片完整性；常规信息不做常驻黑色浮条。

### 4.3 刷新

当前章节保留一个常用「刷新」操作；菜单承载「刷新整本合集」「重试未保存图片」
和「打开原网页」。避免为不同刷新范围同时放置多个常驻按钮。

整本刷新冻结本次章节清单，后台逐章检查。显示总数及已更新、未变化、失败、取消数量；
允许继续阅读、取消剩余任务、仅重试失败项。新增章节不偷偷加入已启动的刷新批次。
已删除章节跳过，改名/排序不导致错误覆盖。

有可用新版时：

- 未打开章节可发布新版；当前阅读会话继续持有自己的快照。
- 正在阅读的章节提示「内容已更新」，在可保持位置时应用；不能因后台更新跳回开头、
  关闭选区或覆盖未保存的批注草稿。
- 用户采用新版后，按文本版本及引用锚点恢复位置；不确定时提示并提供章节级回退。

不增加定时刷新作为首期前置条件。以后可增加自动检查，须保持本地打开不依赖网络。

### 4.4 删除与管理

- 删除章节需说明它将从合集移除；关联笔记和历史摘录保留来源说明，不静默丢失。
- 删除合集沿用现有书籍删除确认语义，显式处理应用内数据与受管资源。
- 不把网页合集冒充 Markdown 文件夹书；任何操作都不得写入或删除用户 Markdown 源目录。
- 空合集和全部获取失败的合集仍可管理；不能出现点击书籍后无反馈的状态。

## 5. 状态表达

状态按不同维度记录，避免一个 `success` 同时代表正文、图片、网络和索引：

| 维度 | 典型状态 | 界面含义 |
| --- | --- | --- |
| 本地正文 | 未保存 / 可读 / 本地损坏 / 已移除 | 是否可以离线打开 |
| 阅读内容完整性 | 完整 / 部分资源缺失 / 有不支持内容 | 是否遗漏阅读所需内容 |
| 当前操作 | 排队 / 获取 / 提取 / 保存 / 已完成 / 失败 / 取消 | 此次任务进展 |
| 最近检查 | 未检查 / 未变化 / 已更新 / 检查失败 | 不等同于正文可用性 |
| 索引 | 待建立 / 可用 / 已过期 / 失败 | 搜索和 AI 能否使用当前正文 |

例如「可离线阅读 · 2 张图片未保存 · 刷新失败」是合法状态，不能退化成“书籍不可用”。
HTTP 304 只说明响应未变化，不证明本地文件完整，也不代表缺失图片已补齐。
索引失败不阻止正文阅读。

## 6. 完成口径

功能完成必须覆盖 R1–R9 的整条链路，尤其是：

1. 添加网页 → 正文和图片持久保存 → 断网重启阅读。
2. 单章/整书刷新 → 失败保留旧版 → 取消或重启可恢复。
3. 改名/排序/刷新后，进度、批注和搜索定位仍正确或明确降级。
4. 新备份恢复到不同根目录后断网可读；旧版备份仍能恢复。

W0 已建立隔离抽取/原生模型原型，并纳入用户提供的 Anthropic、LangGraph 页面；
应用合集入口、数据库迁移、网页图片持久化与刷新尚未接入。
本轮还修复了原生阅读器列表链接的样式与点击范围错位，验证和安装证据单独记录，
不能把这项共享阅读器修复当作网页合集上线。详见[交付计划](03-delivery-plan.md)。
